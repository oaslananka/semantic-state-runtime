# Install the Developer Preview MCP runtime from source

**Status:** local, unreleased developer preview. This is not a public npm package, an `npx` install, an MCP Registry entry, or a hosted service.

You can install the compiled **stdio MCP server** into a separate final directory without publishing it. The installation bundles production dependencies needed to run it; only the installation step needs the pnpm workspace. The runtime needs Node.js 24.12+ and an explicit SSRL configuration.

## Source-based installation

Requirements on the build machine: Node.js 24.12+, pnpm 12.14.0 (via Corepack or an existing pinned pnpm installation), and Git.

~~~bash
git clone https://github.com/oaslananka/semantic-state-runtime.git
cd semantic-state-runtime
pnpm install --frozen-lockfile
pnpm preview:install -- ../ssrl-preview-runtime
node ../ssrl-preview-runtime/dist/cli.js --help
~~~

The command builds the source and deploys only production dependencies to **one new directory**, then checks the installed CLI.
The installed folder includes its own **MIT LICENSE notice** and the
local runtime/configuration guide under docs/. Select the **final directory** deliberately. The installer refuses to overwrite a path that already exists, refuses destinations inside the source checkout, and does not delete existing files.

**Windows:** pnpm currently emits absolute directory junctions in this preview deployment. The installed runtime works at its original destination but **moving or renaming the directory can break it**. Choose the final path first; for a different path, run the preview installation into another *new* directory. Do not promise a relocatable Windows ZIP.

**Linux:** a separate clean-clone acceptance on Linux verified that the deployed CLI could run after a directory rename; the repo's preview smoke test additionally checks the actual MCP tool calls after relocation. This does not establish that the same artifact can run on another OS/architecture.

## Connect an MCP client

The installed executable is:

~~~text
node /absolute/path/to/ssrl-preview-runtime/dist/cli.js /absolute/path/to/your-ssrl.config.json
~~~

Use this command and arguments as your MCP client's **stdio server** configuration. The example shows POSIX-style paths; use the equivalent final directory on Windows.

The config file is **not automatically generated for real personal data**. Follow the [explicit local config contract](local-node-runtime-v1.md) to select the Markdown directories, canonical entities, trusted provider, field policies, and principal scopes you actually authorize. The CLI does not search your disk on its own. For a read-only client, avoid granting write operations.

No model key is required for the MCP server or its deterministic test. A particular chat application may require its own inference account.

## Independent acceptance

After a normal repo build, run:

~~~bash
pnpm test:preview-install
~~~

The offline smoke test creates its **own disposable** installation, checks existing-target refusal, and uses the installed runtime rather than the checkout's CLI for real MCP calls. It verifies source authority, `context.compile`, plan/apply permissions, denial of hidden evidence, stale-proposal rejection, and restart persistence. On Linux it reruns the MCP test after relocating the installation. On Windows it verifies the original final location, not relocation.

The deployed manifest may include `file:///` references generated by pnpm. The installation is **already provisioned**, so do **not** run `npm install` inside it or claim it is a valid distributable npm tarball. This is a step toward a standalone package, not the packaging/release acceptance itself.

**Still unverified:** public registry installation, clean human-user setup with personal files, a signed release, and live multi-device replication. These need their own acceptance before release claims.

## Local npm tarball preview (unpublished)

For development and packaging acceptance, you can build a self-contained tarball without adding a hosted service or publishing to a registry. The package is intentionally marked **private** and cannot be published as-is.

~~~bash
pnpm install --frozen-lockfile
pnpm preview:pack -- ../ssrl-npm-preview
cd ../ssrl-npm-preview
npm pack
~~~

The generated directory contains a bundled stdio CLI, MIT license, and the local runtime configuration guide. It does **not** include the pnpm workspace or `file:///` runtime dependencies. The local tarball is an experimental distribution candidate, not a supported npm release.

The source repository's `pnpm test:preview-pack` runs `npm pack`, installs the resulting tarball **offline into a different directory**, and checks `--help`, `--version`, and real policy-scoped MCP stdio tool calls. This test must pass on the exact PR head before any public distribution is considered.

The package still needs independent human first-run, distribution-name verification, Windows/Linux installation evidence and a separate release approval. No public npm or MCP Registry entry has been created.
